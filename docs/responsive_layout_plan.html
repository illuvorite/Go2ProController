真机上踩到并修掉的两个硬 bug（都只在真机暴露，值得记住）：

1结论先行

问题根子
现在是「一个布尔开关 + 一堆写死的像素」
不是没有适配，而是只有"桌面/手机"两档，中间全空
最该先做的一件事
把 ImGui 的坐标单位归一成 dp
否则所有断点数值都没有意义（见第 6 节 P0-1）
断点怎么切
按宽度 4 档：<600 / 600–899 / 900–1279 / ≥1280 dp
再用「高度」和「触摸」两条规则做叠加修正
布局怎么变
三栏 → 双栏 → 单栏+抽屉/底部页签
栏宽全部改为「按比例算 + 上下限夹取」，不再写死
摇杆怎么放
宽屏内嵌在遥控栏，窄屏改为悬浮在屏幕两下角
位置由公式推导 + 让开安全区，且内容预留高度用同一个公式算
预期效果
手机竖屏能用、平板不再被当手机、桌面 1440×880 完全不回归
安全操作（急停）在任何尺寸下都常驻可见
打个比方：现在的做法像给房子装了一扇"固定尺寸的门"——门框钉死了，房子变大变小它都不管，只好在旁边再开一个"手机专用门"，而且只能二选一。响应式要的是"推拉门 + 折叠门"：门框跟着墙走，宽了就三开间、窄了就一开间。

3断点体系：4 档宽度 × 3 档高度 已作废

这个界面的瓶颈不只是宽度。遥控页是"安全关键操作区"：急停、阻尼、参数、快捷键、双摇杆都要能一眼看到、手指够得着——所以高度和宽度一样重要。因此用二维断点。

4三种布局模式详解 已作废

A 三栏工作台 E / L 宽 × R / T 高（≥900 × ≥480dp）· 平板横屏、桌面

就是现在桌面的样子，但所有宽度从"写死"改成"算出来"，并保证日志栏有下限。

区域规则
顶栏≥1280dp 保持 3 行（124dp）；900–1279dp 压成 2 行（92dp）：把「本地钥匙 / 重载钥匙」这一行移到「设置」页，IP 输入框收到 160dp，长提示文字转成图标 + 长按提示
左栏clamp(宽×0.27, 280, 420) → 1440 时约 389dp（与现状 392 几乎一致，不回归）；下限 280dp 是为了 900–1110dp 这一档（平板横屏）仍能凑出三栏
遥控栏clamp(宽×0.33, 360, 520) → 1440 时约 475dp（现状 468）；下限 360dp 同上
日志栏占剩余；算出来 ≥ 280dp 才常驻，否则自动折叠为「日志 ▾」浮层。这样 900–1100dp 时不会出现 150px 宽的鸡肋日志栏
摇杆内嵌在遥控栏，半径 74dp，双杆间距 24dp（与现状一致）
高度修正高度 < 480dp 时：日志折叠为浮层、参数滑条进折叠区、动作库按钮单列

B 双栏 M 宽 × R / T 高（600–899 × ≥480dp）· 平板竖屏、小平板横屏

平板竖屏是最容易被忽略、但实际最好用的一档：左边常驻设备/动作库，右边纵向分成"遥控上、日志下"。

区域规则
顶栏压成 1 行 56dp：[≡] 1/4 台 · 运行中 ｜ [扫描][＋][连接] ｜ [🔒][⋮]，其余进 ⋮ 菜单
左栏常驻，clamp(宽×0.40, 280, 340) → 768 时约 307dp
右栏纵向两段：遥控区占上方（内容自适应，最少 420dp），日志占下方剩余；日志可一键收起，收起后遥控区吃掉全部高度
摇杆内嵌在遥控栏底部（平板竖屏时双手持握、拇指正好落在右栏下角），半径 clamp(右栏宽×0.17, 56, 84)
动作库按钮按右栏/左栏宽度自适应 2 列；滑条宽 = min(220, 栏宽−80)
高度修正高度 < 480dp（小平板横屏 800×600）时：左栏降级为抽屉、日志折叠，只剩单栏

C 单栏 + 悬浮双摇杆 C 宽任意高，或 M 宽 × S 高（<600dp 任意，或矮屏）· 手机横竖屏

这是改动最大的一档，也是现在完全不可用的一档（竖屏锁死了）。内容单栏铺满，摇杆脱离文档流浮到屏幕下两角，导航按高度二选一。

区域规则
导航高度 ≥480dp（竖屏）：底部页签 5 项（遥控 / 设备 / 动作 / 设置 / 日志），高 56dp + 底部安全区
高度 <480dp（横屏）：顶栏左侧 [≡] 侧滑抽屉（宽 min(420, 宽×0.62)），省下纵向空间给遥控
顶栏1 行 52–56dp：品牌缩写 + 状态灯 + 受控台数 + [🔒 隐私] + [⋮]；右侧常驻速度读数 vx/vy/vz + 下发状态（小字），避免被摇杆挡住
遥控页
竖屏（高 ≥480dp）		纵向空间充裕，全部常显：状态卡（连接/电量/模式）→ 急停（全宽 88dp）→ 阻尼（全宽 ≥48dp，与急停间距 ≥12dp 防误触）→ 快捷 4 键（2×2，每键 ≥64dp）→ 「参数」折叠区（线速度/角速度/步速）
遥控页
横屏矮屏（高 <480dp）		纵向只有约 338dp，塞不下全部内容，必须做取舍。算一下：摇杆占底部 156dp + 留白 24dp，只剩约 158dp。
所以首屏只留：状态条（一行 38dp）+ 急停（72dp）+ 阻尼（48dp）；

摇杆悬浮，半径 clamp(min(宽,高)×0.20, 60, 128)；左内缩 radius×0.95 + 安全区左 + 16；圆心高度 高 − 安全区底 − radius − 24；竖屏时再往上让开底部页签

5.2 摇杆几何（全部改为推导式）

// 现在（写死 + 魔法数）
radius = min(128, max(74, h * 0.22));
inset  = radius * 0.95 + 44;          // 44 是什么？没人知道
cy     = h - radius - 90;             // 90 是硬编码的"底部留白"
if (mob) ImGui::Dummy(ImVec2(0, 250)); // 预留高度又是另一个数

// 改为
radius = clamp(min(w, h) * 0.20f, 60.0f, 128.0f);
insetX = radius * 0.95f + safe.left + 16.0f;
cy     = h - safe.bottom - radius - 24.0f - (底部页签 ? 56.0f : 0.0f);
预留高 = (h - cy) + radius + 24.0f;   // ← 与摇杆同一个来源，永不脱节

关键点：摇杆位置和内容预留高度必须来自同一个函数。现在这两个值是分开写的（一个算 h-radius-90，一个写 250），屏幕一变就错位——这正是矮屏上摇杆压住按钮的根因。

6重点适配细节（按优先级）

每条都给了"现象 → 原因 → 改法（文件位置）"，可以直接照单施工。

P0 · 不做这些，断点就是白做

#事项做法
P0-1 坐标单位归一（DPI）
最关键的一条		 SDL2 在 Android 上返回的是物理分辨率，ImGui 单位 = 物理像素，所以 3x 屏上 54 单位按钮实际只有约 18dp。做法：取设备密度（JNI 读 displayMetrics.density，或 SDL_GetDisplayDPI()/160；桌面用 glfwGetWindowContentScale），然后在 ImGui_ImplSDL2_NewFrame() 之后覆盖：
io.DisplaySize = ImVec2(物理宽/density, 物理高/density);
io.DisplayFramebufferScale = ImVec2(density, density);
这样 ImGui 单位 = dp，断点数值才有意义，字也按物理分辨率栅格化（不糊）。
落地前先实测确认一次：在目标机型上打印 SDL_GetWindowSize / SDL_GL_GetDrawableSize / density 三个值。
P0-2 改用动态字号 删掉 kMobileFontScale 烘焙逻辑（theme.cpp 的 loadUiFontsFromMemory），改为只加载一次字体，字号用 ImGui::PushFont(font, 21.0f) 按断点给。横竖屏切换、跨断点都不用重载图集。
P0-3 样式缩放不能累乘 ScaleAllSizes 是就地相乘（已核对 imgui.cpp 实现：_MainScale *= f 仅作记录，各字段直接乘）。所以切断点前必须还原：
static ImGuiStyle base = ImGui::GetStyle(); // 启动时存快照
ImGui::GetStyle() = base; ImGui::GetStyle().ScaleAllSizes(k);
P0-4 用 LayoutSpec 取代 mobileLayout 现在 ui.mobileLayout 是一个 bool，散落着 mob ? 452 : 392 这类三元表达式（ui.cpp 里至少 10 处）。改成：
struct LayoutSpec { Mode mode; float leftW, ctrlW, logW, btnH, fontT, fontB, fontS, joyR; bool logInline, touch; };
由 makeLayout(w, h, touch) 算出来，所有面板尺寸/字号只从 spec 取值。这是让后面三种模式可维护的前提。
P0-5 触摸判定按输入方式，不按平台 收到 SDL_FINGERDOWN 置 touch=true，收到鼠标/键盘事件置 false，2 秒无触摸回落。触屏笔记本、平板外接鼠标都能自动切换按钮尺寸。

P1 · 布局与交互本体

#事项做法
P1-1顶栏自适应 + 溢出折叠顶栏高度由"行数 × 控件高 + 间距"算出来，不再写死 124/176。第二行加溢出处理：宽度不够时依次缩短 IP 输入框 → 隐藏长提示文字（转长按提示）→ 次要按钮收进 ⋮ 菜单。保证「全部断开」在任何宽度下都点得到。
P1-2左栏宽度与降级leftW = clamp(w×0.27, 280, 420)；若 w − leftW − ctrlMin < 280（放不下日志），则左栏降级为侧滑抽屉（宽 min(420, w×0.62)）。
P1-3动作库按栏宽分列列数 = max(1, floor((栏宽 − padding) / 最小按钮宽))，按钮宽 = (栏宽 − padding − (列数−1)×间距) / 列数。替换写死的 actW1/actW2/actW3；滑条宽 = min(250, 栏宽 − 标签宽 − 间距)。
P1-4急停的安全属性急停永远全宽、永远在视口内、单栏模式下吸底固定不随内容滚动；高度按高度档取 72/88dp（单栏）或 56/64dp（多栏）；阻尼按钮与急停间距 ≥12dp 防误触；急停可用性不依赖连接状态（断线时也要能按）。
P1-5摇杆几何 + 预留高度同源见 5.2。另外要修一个真实的交互隐患：现在 sticks.down() 在 ImGui 之前抢事件，抓取半径是 radius×1.9，落在急停/阻尼按钮上的手指可能被摇杆吃掉。改法：先判断是否命中安全操作区（急停/阻尼），命中则直接放给 ImGui，摇杆不得消费。
P1-6安全区（刘海 / 圆角 / 手势条）Java 侧读 WindowInsets 传给 native（或先保守用 top/bottom 24dp、left/right 40dp）。用于顶栏内边距、底部页签高度、摇杆落点。左右边缘 20dp 是系统手势区，摇杆必须内缩避开——现在那个 +44 就是在做这件事，要保留并参数化。
P1-7日志分级展示≥1200dp 常驻（≥380dp）；900–1200dp 常驻窄栏 + 软换行（去掉横向滚动条）；<900dp 改浮层抽屉，入口按钮带错误数角标；手机竖屏作为独立页签。长日志用 ImGuiListClipper 降开销。
P1-8开放竖屏 + 旋转重算清单里 sensorLandscape → fullSensor；因为 configChanges 已包含 orientation|screenSize，Activity 不会重建，所以必须自己在每帧检测 DisplaySize 变化时重算 LayoutSpec（并把样式从快照重新 Scale）。建议：遥控中（有手指按在摇杆上）忽略方向变化，松手后再切，避免操作中摇杆位置跳变。
P1-9遥控时保持屏幕常亮机器人遥控场景里息屏会断连，属于安全问题。加 FLAG_KEEP_SCREEN_ON（或 SDL 的对应 hint），仅在"已连接且遥控页在前台"时生效。
P1-10软键盘遮挡手动加 IP / 输入钥匙时键盘会盖住半屏：输入框改为居中弹窗 + SetKeyboardFocusHere()，并在键盘弹出时把弹窗上移。

P2 · 体验打磨

#事项做法
P2-1手势与震动三指同按 = 急停（可选安全兜底）；急停 / 阻尼 / 连接成功给短震动反馈（触屏"按不准"，震动是重要的确认感）。
P2-2左右手习惯设置项：摇杆左右手可交换（左手模式把"移动杆"放右侧），平板横屏双手持握时很有用。
P2-3分屏 / 自由窗口Android 12+ 平板分屏、Windows 半屏会自动命中 E 或 M 档，无需特殊处理——但要确保 onConfigurationChanged 时重算 LayoutSpec 且不丢状态。
P2-4键盘可达性平板接键盘 / 桌面窄窗：保留空格急停；Tab 焦点顺序按"安全优先"排（急停 → 阻尼 → 摇杆 → 快捷 → 动作）。
P2-5性能与发热窄屏下日志刷新降频；渲染限帧（移动 60fps / 低电 30fps）；动作库长列表用 clipper。
